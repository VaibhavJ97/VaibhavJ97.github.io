## What is this?

This repository hosts a personal portfolio site combined with an interactive scientific web application built around my M.Sc. thesis: **"Impact of Climate Change on the Geothermal Potential of Closed Systems Using GIS and Python"** (KIT, 2025).

The site has two parts:

1. **A CV homepage** with full biography, skills, experience, education, internships, and certifications
2. **A Master Thesis Project page** with an interactive map explorer that lets visitors browse all 24 maps generated by the thesis simulation, switch climate models and scenarios, change colormaps, and click on any pixel to see exact extraction-rate values

Everything is hosted for free on GitHub Pages, and the interactive maps render entirely in the user's browser using vanilla JavaScript.

## The story: how this was built

### Where it started: a Jupyter notebook and 16 GeoTIFFs

When the thesis project began, all the science lived inside a single Jupyter notebook (`Single_BHE_Analysis_GEE_CMIP6_Folium.ipynb`) running on my laptop. The notebook does several things:

1. Loads CMIP6 climate projections (8 General Circulation Models × 2 SSP scenarios = 16 GeoTIFFs) acquired through Google Earth Engine
2. For every pixel of every TIFF, runs a semi-analytical Borehole Heat Exchanger (BHE) model based on Finite Line Source (FLS) theory (Rivera, 2017), using `scipy.optimize.brentq` to solve for the sustainable extraction rate at the minimum allowed fluid temperature
3. Produces 6 output layers per scenario: Maximum Heat Extraction Rate, Usable Power, Sustainable variants, all over 50-year and 100-year operating horizons
4. Renders the results as interactive [folium](https://python-visualization.github.io/folium/) maps with togglable layers and color legends

The notebook output was beautiful but lived only on my machine. To put it online, I needed a different architecture.

### Why the obvious approaches did not work

The natural first thought was: just render the maps live. A visitor opens the page, picks a model, and the Python notebook runs and produces a map.

This is impossible on free static hosting because:

- **GitHub Pages, Netlify, Vercel, Cloudflare Pages** can only serve static files. They do not run Python.
- **Hugging Face Spaces and Streamlit Cloud** can run Python, but the BHE model takes 15-30 minutes per run on a free CPU. No visitor will wait that long for a single map.
- **Re-implementing the FLS heat-transport math in JavaScript** would take weeks and would not match the scientific reference implementation.
- **Zenodo** is for archival storage with citable DOIs, not for serving live web content.

I needed an architecture that serves the *real* model output without re-running anything in the browser.

### Iteration 1: extract the rendered HTML maps

The first working approach was to take advantage of the fact that the notebook had already produced 14 fully-rendered folium HTML files inside its saved output cells. A small Python script extracted these from the `.ipynb` file (parsing the `outputs` field of each code cell, decoding the embedded `srcdoc` attribute) and saved them as standalone HTML.

The website's "explorer" page then used a sidebar with dropdowns and an `<iframe>` that loaded the matching HTML file. Switching climate models swapped the iframe source, and the visitor saw the authentic notebook output, complete with all 6 togglable layers, two color legends, and the Germany boundary.

This worked, but it had limits:

- The map's colormap was baked into the PNG overlays. The website could not change colors without re-running the notebook.
- The iframe approach felt clunky on mobile.
- Layer toggles inside the iframe were locked to whatever folium had generated.

### Iteration 2: export numeric arrays as JSON, render in JavaScript

The second architecture is what ships in production today.

A small Python script (`files/export_to_json.py`) runs once locally after the notebook finishes. It walks through every `*_ssp245` and `*_ssp585` variable in the notebook kernel, extracts the 6 output layers as numpy arrays, rounds them to 2 decimal places, replaces NaN with `null`, and writes one compact JSON file per model+scenario combination plus four ensemble JSON files per scenario (Mean, P25, P50, P75 across the 8-model stack, computed with `np.nanmean` and `np.nanpercentile`).

The total output is roughly **373 KB of JSON** for all 24 maps combined. That is small enough to serve from GitHub Pages with no performance issues.

The website's map explorer (`thesis/map-fullscreen.html` and inline at `thesis/index.html`) then:

1. Fetches the matching JSON file when the user picks a model+scenario
2. Renders a small HTML5 canvas (one pixel per data point, e.g. 13×16) using [chroma-js](https://gka.github.io/chroma.js/) for the colormap
3. Upscales the canvas 50x with `imageSmoothingEnabled = false` for crisp pixelated edges (no browser blur)
4. Wraps the result in a [Leaflet](https://leafletjs.com) `imageOverlay` positioned with the GeoTIFF's geographic extent
5. Overlays Germany's national boundary (fetched from a public Natural Earth GeoJSON)
6. On any pixel click, reverse-projects the lat/lon to array indices and shows the exact W/m or W value in a popup

Because the colormap is applied at render time in the browser, switching from Viridis to Plasma to Magma to Reds happens in 50 ms with no server round-trip. Layer toggles are real Leaflet image overlays that show/hide instantly.

## Tech stack

### Backend (one-time, runs locally)

- **Python 3.12** with `numpy`, `scipy`, `joblib`, `rasterio`, `geopandas`
- **Google Earth Engine Python API** for CMIP6 acquisition
- **folium** (used for the original notebook visualization)
- **Jupyter Notebook** as the analytical environment
- A custom export script that converts in-memory numpy arrays to JSON

### Frontend (runs in the visitor's browser)

- **Vanilla HTML, CSS, JavaScript** - no build step, no framework
- **[Leaflet 1.9](https://leafletjs.com)** for the map and image overlays
- **[chroma-js 2.4](https://gka.github.io/chroma.js/)** for colormap interpolation (16 colormaps total)
- **HTML5 Canvas API** for rendering numpy arrays as image data
- **Google Fonts** (Fraunces, JetBrains Mono, Inter) for typography
- **CARTO** light tiles as the base map
- **Natural Earth** GeoJSON for the Germany boundary

### Hosting

- **GitHub Pages** (free, public repo)
- **Custom domain**: `vaibhavj97.github.io`
- Total site size: about 5 MB including all 24 JSON map files

### Browser-side rendering pipeline

```
data_json/individual/CanESM_ssp245.json   (one JSON per model+scenario)
        |
        v
fetch() returns a 2D array of floats with NaN as null
        |
        v
For each active layer:
  Create a small canvas (cols x rows, e.g. 13x16)
  For each pixel:
    chroma.scale(colormap).domain([2, 55])(value)  ->  RGB color
    Or transparent if value is null/NaN
        |
        v
Upscale 50x to a larger canvas with imageSmoothingEnabled = false
        |
        v
canvas.toDataURL() -> base64 PNG
        |
        v
L.imageOverlay(pngUrl, [[ymin, xmin], [ymax, xmax]])
        |
        v
Germany boundary GeoJSON drawn on top with bringToFront()
```

## How to reproduce or update the maps

If you fork this repo and want to regenerate the JSON data with different model parameters:

1. Clone the repo locally
2. Open `files/Single_BHE_Analysis_GEE_CMIP6_Folium.ipynb` in Jupyter (or Google Colab)
3. Place all 16 GeoTIFFs from `data/` next to the notebook
4. Run all cells from top to bottom (takes about 25-35 minutes on Google Colab CPU, 60-90 minutes on an older laptop)
5. At the end, paste this in a new cell and run it:
   ```python
   exec(open('export_to_json.py').read())
   ```
6. The script writes a `data_json/` folder with 25 files (~373 KB total)
7. Upload that `data_json/` folder to `thesis/data_json/` in the repo
8. Commit, push, wait 1-2 minutes for GitHub Pages to redeploy

The website automatically picks up the new data on next page load.

## Key thesis findings

- Under SSP 2-4.5 by 2100: shallow ground temperature rises by **+1.7 °C** (±0.6 °C across the CMIP6 ensemble)
- Under SSP 5-8.5 by 2100: shallow ground temperature rises by **+3.1 °C** (±1.1 °C)
- Geothermal heat-extraction efficiency increases by **8-24%** compared to current baseline
- Each 1 °C of subsurface warming substitutes roughly **4 metres** of borehole drilling depth for equivalent heat supply

These results suggest climate change has a measurable, mostly positive effect on the closed-loop shallow geothermal energy potential across Germany - though the ensemble spread is significant and varies by region.

## Lessons learned

A few things worth noting for anyone building something similar:

- **Static + JSON beats dynamic Python** for read-only scientific visualizations. The user experience of an instant page is worth more than the elegance of "re-running the model live."
- **Image rendering in the browser** with `Canvas.imageSmoothingEnabled = false` and CSS `image-rendering: pixelated` is the simplest way to get crisp blocky pixels for low-resolution scientific data.
- **Geographic alignment** between a Canvas-based image and Leaflet's coordinate system requires only the GeoTIFF's bounding box (xmin, xmax, ymin, ymax) plus the array shape. No reprojection needed if everything is already in EPSG:4326.
- **GeoJSON of country boundaries from Natural Earth** is small enough (a few hundred KB) to fetch directly in the browser without preprocessing.
- **`np.nanpercentile` across a stack of arrays** is the cleanest way to compute per-pixel ensemble statistics. It handles missing data gracefully and matches the standard climate-science approach.
